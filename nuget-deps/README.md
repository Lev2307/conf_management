# Визуализатор графа зависимостей NuGet

Учебный проект по дисциплине «Конфигурационное управление»,
практическая работа № 2, вариант 1.

CLI-инструмент для построения графа зависимостей пакетов .NET (NuGet).
Готовые менеджеры пакетов и библиотеки для получения зависимостей
не используются — только стандартная библиотека Python
(`argparse`, `urllib`, `json`, `xml.etree`).

## Этап 1. Минимальный прототип с конфигурацией

Приложение принимает параметры из командной строки и проверяет их.
При ошибке выводится понятное сообщение и программа завершается
с ненулевым кодом. На этом этапе параметры выводились в формате
`ключ = значение` (по заданию — только для этапа 1).

### Параметры

| Параметр | Обязательный | По умолчанию | Описание |
|---|---|---|---|
| `--package` | да | — | имя анализируемого пакета NuGet |
| `--repo` | да | — | URL репозитория NuGet или, при `--test-mode`, путь к файлу тестового репозитория |
| `--test-mode` | нет | выключен | режим тестового репозитория (флаг без значения) |
| `--output` | нет | `graph.png` | имя PNG-файла с изображением графа |
| `--max-depth` | нет | `3` | максимальная глубина анализа зависимостей (от 1 до 50) |

### Проверки параметров

| Параметр | Ошибка |
|---|---|
| `--package` | не задан; пустой; содержит символы, кроме `A-Z a-z 0-9 . - _` |
| `--repo` | не задан; пустой; в обычном режиме — не URL `http(s)://` с адресом сервера; в тестовом режиме — файл не найден или это папка |
| `--output` | пустой; расширение не `.png`; папка для файла не существует; путь указывает на папку |
| `--max-depth` | не целое число; меньше 1 или больше 50 |

## Этап 2. Сбор данных

По имени пакета и URL репозитория программа получает **прямые
зависимости** последней стабильной версии пакета и выводит их на экран.

### Как получаются зависимости (NuGet API v3)

1. **Индекс репозитория.** По адресу из `--repo`
   (например, `https://api.nuget.org/v3/index.json`) скачивается JSON
   со списком служб. В нём ищется ресурс с типом
   `PackageBaseAddress/3.0.0` — адрес хранилища пакетов. Благодаря
   этому шагу поддерживается любой публичный репозиторий NuGet v3,
   а не только nuget.org.
2. **Список версий.** `{хранилище}/{имя пакета}/index.json` — все
   опубликованные версии по возрастанию. Выбирается последняя
   стабильная (без `-` в номере: `-beta`, `-rc` и т. п. пропускаются).
3. **Описание пакета.** `{хранилище}/{имя}/{версия}/{имя}.nuspec` — XML,
   из которого извлекаются все элементы `<dependency>`.

Имя пакета и версия в адресах приводятся к нижнему регистру,
как требует хранилище NuGet.

### Объединение зависимостей

В `.nuspec` зависимости обычно разбиты на группы по целевым
платформам (`net8.0`, `.NETStandard2.0` и т. д.). Программа
**объединяет зависимости всех групп без повторов**. Поэтому, например,
у `Newtonsoft.Json` выводятся зависимости, которые нужны только
старым платформам (.NET Standard 1.x), хотя на сайте nuget.org
для современных платформ указано «No dependencies».

### Обработка ошибок

| Ситуация | Сообщение |
|---|---|
| пакет не найден в репозитории | `Пакет X не найден в репозитории` |
| по адресу `--repo` не JSON (например, обычный сайт) | `Ответ не является JSON: …` |
| в индексе нет `PackageBaseAddress/3.0.0` | `Репозиторий не поддерживает PackageBaseAddress/3.0.0` |
| сервер недоступен или домен не существует | `Не удалось подключиться к …` |
| превышено время ожидания (10 с) | `Превышено время ожидания: …` |
| у пакета нет стабильных версий | `У пакета нет стабильных версий` |
| некорректный XML в `.nuspec` | `Некорректный XML в описании пакета` |

Пакет без зависимостей ошибкой не считается — выводится `(нет)`.
Тестовый режим (`--test-mode`) будет реализован на этапе 3.

Коды завершения: `0` — успех, `1` — ошибка значения параметра или
репозитория, `2` — ошибка разбора командной строки (сообщение argparse).

## Структура проекта

```
├── src/
│   ├── main.py      # точка входа: разбор аргументов, вывод зависимостей
│   ├── config.py    # класс Config, ConfigError и проверки параметров
│   └── nuget.py     # получение и разбор данных из репозитория NuGet
├── tests/           # тесты pytest (без обращения к сети)
├── scripts/         # bat-скрипты и тестовые данные
├── pytest.ini
└── README.md
```

## Запуск

Требуется Python 3.10+, сторонние пакеты для работы не нужны.

```
py src\main.py --help
py src\main.py --package Newtonsoft.Json --repo https://api.nuget.org/v3/index.json
```

## Тесты

```
py -m pip install pytest flake8
py -m pytest
py -m flake8 --max-line-length 80 --max-complexity 10 src tests
```

Тесты этапа 2 не обращаются к сети: функции скачивания подменяются
через `monkeypatch` заранее подготовленными ответами репозитория.

## Демонстрационные скрипты

| Скрипт | Что показывает |
|---|---|
| `test_ok.bat` | правильные запуски с разными параметрами (этап 1) |
| `test_errors.bat` | обработку ошибок для каждого параметра (этап 1) |
| `test_deps.bat` | прямые зависимости нескольких пакетов и ошибки репозитория (этап 2) |

Запуск из PowerShell в корне проекта: `.\scripts\test_deps.bat`
